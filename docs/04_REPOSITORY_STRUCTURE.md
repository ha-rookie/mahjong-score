# Repository Structure

## 1. 文書目的

この文書は、Repository内のファイル・フォルダ配置、責務、生成物、命名規則の正本とする。

## 2. App固有構成

```text
/
├─ .github/
│  ├─ ISSUE_TEMPLATE/
│  ├─ workflows/
│  │  ├─ deploy-production.yml
│  │  ├─ fork-monitor.yml
│  │  └─ template-validation.yml
│  └─ PULL_REQUEST_TEMPLATE.md
├─ docs/
│  ├─ design/
│  ├─ adr/
│  └─ *.md
├─ src/
│  ├─ App.tsx
│  ├─ main.tsx
│  ├─ index.css
│  └─ vite-env.d.ts
├─ index.html
├─ package.json
├─ tsconfig.json
├─ tsconfig.app.json
├─ tsconfig.node.json
├─ vite.config.ts
├─ wrangler.jsonc
├─ eslint.config.js
├─ .gitignore
├─ AGENTS.md
├─ CHANGELOG.md
└─ README.md
```

Phase 1のbootstrap時点では、Worker API用entrypointを作成しない。Phase 2でAPIを追加する際に `worker/` とWorker用TypeScript設定を追加する。

## 3. Directory Responsibilities

| Path | Responsibility | Source/Generated | Production Artifact |
| --- | --- | --- | --- |
| `.github/` | CI、Issue、PR運用 | Source | No |
| `docs/` | 設計の正本 | Source | 原則No |
| `src/` | React application source | Source | Build後Yes |
| `dist/` | Vite / Cloudflare Vite plugin build output | Generated | Yes |
| `public/` | 承認済み静的Asset（後続Issueで追加） | Source | Yes |

## 4. Source vs Generated

| Path | Generated By | Input Source | Reproducible | Review Method |
| --- | --- | --- | --- | --- |
| `dist/` | Vite + Cloudflare Vite plugin | `src/`, `index.html`, config | Yes | CI build |

`dist/` と `.wrangler/` はcommitしない。

## 5. Naming

- Directory/file名: 原則lowercase + kebab-case / 技術慣習に従う
- React component: PascalCase
- Test: 実装との対応が分かる名前
- Asset: 内容が分かる安定名
- ADR: `ADR-0001-short-title.md`

## 6. Dependency Direction and Placement

Phase 1の機能実装では以下を基本とする。

- UI → `src/` presentation
- 純粋な麻雀計算 → domain/coreへ分離
- localStorage → infrastructure/repositoryへ分離
- UIからlocalStorageを直接操作しない
- Runtime APIはPhase 1では作らない

機能実装時に必要なsubdirectoryを追加し、空Directoryは作らない。

## 7. Forbidden Content

Repositoryへcommitしない。

- API key
- token
- private key
- password
- 本番秘密値
- 不要な個人情報
- 実在メンバーの成績データ
- ローカル環境固有の秘密設定
- ライセンス上commit不可のAsset

## 8. Asset placement

後続のAsset Issueで以下を利用する。

- `assets/`: 承認済みmaster / 生成元候補
- `public/assets/`: OGP等の本番静的Asset
- `public/icons/`: favicon / PWA icon等

Binary Assetは `docs/HUMAN_AI_COLLABORATION.md` のGR-002に従いHuman Uploadを標準とする。
